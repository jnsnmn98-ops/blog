# 클로드 코드의 핵심 기능 5가지 리서치

- 조사 기준일: 2026-11-03
- 조사 범위: Claude Code의 현재 동작을 기준으로, 사용자가 직접 설정해 작동 방식을 바꾸는 다섯 기능(CLAUDE.md와 메모리, 스킬, 서브에이전트, 훅, MCP)을 다룹니다. "핵심 기능"이라는 말이 모호해서, 공식 문서가 "각 확장 기능은 서로 다른 문제를 푼다"며 나란히 드는 다섯 가지로 해석했습니다. 공식 문서에 '핵심 기능 5가지'라는 분류가 있는 것은 아닙니다. 파일 편집, 명령 실행 같은 기본 도구와 플러그인, 예약 작업은 맥락 설명에만 씁니다.
- 확인한 소스 수: 21개 (Anthropic 공식 문서와 블로그 16개, 표준 공식 사이트 2개, 개인 전문가 글 3개)

## 핵심 요약

Claude Code는 코드베이스를 읽고 파일을 고치고 명령을 실행하는 에이전트형 코딩 도구입니다. 터미널, IDE, 데스크톱 앱, 브라우저에서 쓸 수 있습니다 [1]. 공식 문서는 CLAUDE.md가 항상 켜진 맥락을, 스킬이 필요할 때 쓰는 지식과 워크플로를, MCP가 외부 연결을, 서브에이전트가 격리를, 훅이 자동화를 맡는다고 구분합니다 [2]. 다섯 기능을 가르는 기준은 세 가지입니다. 언제 컨텍스트에 로드되는지, 컨텍스트 비용이 얼마인지, 모델의 판단에 맡기는지 아니면 시스템이 강제하는지입니다 [2][11]. 공식 문서가 권하는 순서는 한꺼번에 설정하지 말고 CLAUDE.md로 시작해, 필요가 생길 때마다 하나씩 더하는 것입니다 [2]. 조사 시점의 최신 버전은 2026년 10월 31일에 나온 2.1.316입니다 [15].

해석: 글의 뼈대로는 "다섯 기능은 서로 대체재가 아니라 역할이 다른 층이다"가 가장 잘 맞습니다. 공식 문서, 공식 블로그, 독립 저자의 글이 모두 이 구도로 설명합니다 [2][16][19].

## 다섯 기능 한눈에 비교

| 기능 | 역할 | 언제 로드되나 | 컨텍스트 비용 | 강제성 | 쓰는 시점 |
| --- | --- | --- | --- | --- | --- |
| CLAUDE.md | 세션마다 읽는 지속 지침 | 세션 시작 시 전체 | 매 요청 발생 | 권고 (모델이 판단) | Claude가 같은 규칙을 두 번 틀렸을 때 |
| 스킬 | 재사용하는 지식과 절차 | 시작 시 설명만, 사용 시 본문 | 낮음 (설명은 매 요청) | 권고. 다만 사용자만 호출하게 제한 가능 | 같은 절차를 세 번째 붙여 넣을 때 |
| 서브에이전트 | 격리된 작업자, 요약만 반환 | 생성될 때 | 메인과 분리 | 위임 범위와 도구를 설정으로 제한 | 곁가지 작업의 출력이 대화를 덮을 때 |
| 훅 | 수명주기 이벤트에 자동 실행 | 이벤트 발생 시 | 0 (출력을 돌려줄 때만 발생) | 결정적으로 실행 | 묻지 않아도 매번 일어나야 할 때 |
| MCP | 외부 서비스와 도구 연결 | 시작 시 도구 이름, 필요 시 스키마 | 사용 전까지 낮음 | 외부 도구 호출은 권한 규칙 적용 | 다른 도구의 내용을 계속 복사해 붙여 넣을 때 |

표의 로드 시점, 비용, 쓰는 시점은 공식 문서의 표를 정리한 것입니다 [2]. 강제성은 공식 모범 사례의 구분을 따랐습니다 [11]. 서브에이전트와 MCP의 강제성 칸은 공식 분류에 없어서 [5][9]의 내용을 바탕으로 에이전트가 쓴 해석입니다.

## 1. CLAUDE.md와 메모리: 세션을 넘어 이어지는 맥락

**왜 필요한가.** 모든 세션은 빈 컨텍스트로 시작합니다. 지식을 다음 세션으로 넘기는 장치는 두 가지입니다. 사람이 쓰는 CLAUDE.md와 Claude가 스스로 쓰는 자동 메모리(auto memory)입니다 [3].

| 항목 | CLAUDE.md | 자동 메모리 |
| --- | --- | --- |
| 작성자 | 사용자 | Claude |
| 내용 | 지침과 규칙 | 학습 내용과 패턴 |
| 범위 | 프로젝트, 사용자, 조직 | 저장소 단위, 워크트리끼리 공유 |
| 로드 | 매 세션 | 매 세션 (앞 200줄 또는 25KB) |

**파일 위치.** 범위가 넓은 순서대로 조직 관리 정책 파일, `~/.claude/CLAUDE.md`(개인 전역), `./CLAUDE.md` 또는 `./.claude/CLAUDE.md`(팀 공유), `./CLAUDE.local.md`(개인 프로젝트용, `.gitignore`에 추가)입니다 [3]. 여러 파일은 서로 덮어쓰지 않고 이어 붙습니다. 작업 디렉터리와 그 상위의 파일은 시작할 때 로드되고, 하위 디렉터리의 파일은 Claude가 그곳의 파일을 다룰 때 로드됩니다 [2][3].

**잘 쓰는 법.**
- 파일당 200줄 이하를 목표로 합니다. 길수록 컨텍스트를 더 쓰고 지시 준수율도 떨어집니다 [3]. 공식 블로그와 독립 저자도 같은 기준을 제시합니다 [16][19].
- "코드를 잘 정리하세요" 대신 "2칸 들여쓰기를 쓰세요"처럼 검증할 수 있게 씁니다 [3].
- 코드를 읽으면 알 수 있는 내용은 뺍니다. 공식 모범 사례는 적기 전에 "코드를 읽어서 찾을 수 있는가, 실제로 찾아보겠는가"를 묻고 둘 다 그렇다면 빼라고 권합니다. 남길 내용은 검증 명령, 오해하기 쉬운 코드, 저장소 밖에서 내린 결정, 두 번 이상 고쳐 준 내용입니다 [11].
- `/init`으로 초안을 만들 수 있습니다. 이미 파일이 있으면 덮어쓰지 않고 개선안을 제안합니다 [3].
- `@경로` 가져오기는 파일을 나누는 수단일 뿐 컨텍스트를 줄이지 않습니다. 가져온 파일도 함께 로드되기 때문입니다. 줄이려면 `paths`로 범위를 정한 `.claude/rules/` 규칙이나 스킬로 옮깁니다 [3].

**자동 메모리.** 기본으로 켜져 있고, 사용자(`user`), 피드백(`feedback`), 프로젝트(`project`), 참조(`reference`) 네 종류의 메모를 저장합니다. 코드에서 알아낼 수 있는 내용이나 CLAUDE.md에 이미 있는 내용은 저장하지 않습니다 [3]. 저장 위치는 `~/.claude/projects/<project>/memory/`이며, 색인 파일 `MEMORY.md`와 주제별 파일로 구성됩니다. 기기 안에만 있고 다른 기기나 클라우드로 공유되지 않습니다. `/memory`로 켜고 끕니다 [3].

**최근 변화.** `AGENTS.md`를 직접 읽는 기능은 v2.1.277 이상에서 지원합니다. 기본 설정에서는 작업 디렉터리나 상위에 `CLAUDE.md` 또는 `CLAUDE.local.md`가 없을 때 `AGENTS.md`를 읽습니다 [3]. `/doctor prompt-audit`(v2.1.283 이상)는 낡았거나 서로 충돌하는 지침을 찾아 줍니다 [3].

**한계.** CLAUDE.md는 강제 설정이 아니라 맥락입니다. Claude가 어떻게 판단하든 동작을 막아야 한다면 훅을 씁니다 [3][11]. 공식 모범 사례의 팁도 같은 내용입니다. 강조를 계속 덧붙여도 Claude가 놓친다면 그 줄은 훅으로 옮길 대상이라는 것입니다 [11].

## 2. 스킬: 필요할 때만 불러오는 지식과 절차

**정의.** 스킬은 지식, 워크플로, 지침을 담은 마크다운 파일입니다. `/deploy`처럼 직접 호출할 수도 있고, Claude가 관련 있다고 판단해 자동으로 불러오기도 합니다. 공식 문서는 스킬을 가장 유연한 확장 기능이라고 부릅니다 [2]. 형식은 폴더 안의 `SKILL.md` 파일이며, YAML 머리말(frontmatter)과 본문으로 구성됩니다 [4].

**두 종류.** 참조형은 API 스타일 가이드처럼 세션 내내 쓰는 지식이고, 실행형은 `/deploy`처럼 특정 작업을 시키는 절차입니다 [2].

**왜 컨텍스트에 유리한가.** 시작할 때는 이름과 설명만 로드하고 본문은 쓸 때 로드합니다 [2]. Agent Skills 표준은 이 방식을 점진적 공개(progressive disclosure)라고 부르며 발견, 활성화, 실행의 세 단계로 설명합니다 [18]. 그래서 긴 참고 자료를 CLAUDE.md 대신 스킬에 두면 비용을 아낄 수 있습니다 [2].

**저장 위치.** 개인용은 `~/.claude/skills/<이름>/SKILL.md`, 프로젝트용은 `.claude/skills/<이름>/SKILL.md`입니다. 프로젝트용을 커밋하면 팀이 함께 씁니다. 플러그인에 넣을 수도 있습니다 [4]. 이름이 겹치면 조직 관리 > 개인 > 프로젝트 순서로 적용됩니다 [2].

**호출 제어.**
- `disable-model-invocation: true`: Claude가 자동으로 호출하지 못합니다. 배포처럼 부작용이 있는 작업에 씁니다. 설명도 컨텍스트에 올라가지 않아 호출 전 비용이 0입니다 [2][4].
- `user-invocable: false`: `/` 메뉴에서 숨기고 Claude만 씁니다. 배경 지식용입니다 [4].
- `context: fork`: 서브에이전트에서 격리해 실행합니다 [2][4].

**예시 (공식 문서 형식 기준).**

```yaml
---
name: deploy
description: 애플리케이션을 프로덕션에 배포합니다
disable-model-invocation: true
---

$ARGUMENTS 를 프로덕션에 배포하세요:
1. 테스트 스위트 실행
2. 애플리케이션 빌드
3. 배포 대상에 푸시
4. 배포 성공 여부 확인
```

**커스텀 명령과의 관계.** `.claude/commands/`는 스킬로 통합됐습니다. `.claude/commands/deploy.md`와 `.claude/skills/deploy/SKILL.md`는 모두 `/deploy`를 만듭니다. 기존 파일은 계속 작동하지만 새로 만든다면 스킬 형식을 권합니다 [4][20].

**기본 제공 스킬.** `/code-review`, `/batch`, `/debug`는 설정 없이 쓸 수 있습니다 [2]. `/batch`는 큰 변경 하나를 워크트리로 격리된 서브에이전트 5~30개로 나눕니다 [6]. 2026년 8월 31일~9월 4일 주간에 나온 `/skill-doctor`는 스킬별 컨텍스트 비용과 사용 빈도를 보여 줍니다 [12].

**이식성.** 스킬 형식은 Anthropic이 처음 개발해 공개 표준으로 내놓았고, 다른 에이전트 제품도 채택하고 있습니다 [18]. 다만 호출 제어, 서브에이전트 실행, 동적 컨텍스트 주입은 Claude Code 확장 기능입니다 [4].

**주의.** 설명이 모호하거나 겹치면 Claude가 엉뚱한 스킬을 불러오거나 필요한 스킬을 놓칠 수 있습니다. 확실히 쓰게 하려면 `/이름`으로 직접 호출합니다 [2]. 절차를 지시문으로 전달하는 방식이라 결과는 달라질 수 있습니다 [2].

## 3. 서브에이전트: 메인 대화를 지키는 격리된 작업자

**정의.** 서브에이전트는 자기만의 컨텍스트 창, 시스템 프롬프트, 도구 권한을 가진 전문 작업자입니다. 검색 결과나 로그처럼 양이 많은 출력을 대신 처리하고 요약만 돌려주므로 메인 대화가 깨끗하게 유지됩니다 [2][5].

**스킬과의 차이.** 스킬은 어느 컨텍스트에나 불러 쓰는 내용이고, 서브에이전트는 분리되어 일하는 작업자입니다. 스킬은 메인 창에 더해지고, 서브에이전트는 별도 창을 씁니다. 둘은 함께 쓸 수 있어서, 서브에이전트가 `skills:` 필드로 스킬을 미리 불러오거나 스킬이 `context: fork`로 격리되어 실행됩니다 [2].

**내장 서브에이전트.** Explore(읽기 전용 탐색), Plan(계획용 조사), general-purpose(범용)가 대표적입니다 [5][19]. Explore와 Plan은 기본적으로 CLAUDE.md와 git 상태를 로드하지 않습니다 [2][5].

**만드는 법.** Claude에게 만들어 달라고 요청하거나, `.claude/agents/`(프로젝트) 또는 `~/.claude/agents/`(개인)에 마크다운 파일을 직접 씁니다. 필수 필드는 `name`과 `description`입니다 [5].

```markdown
---
name: code-reviewer
description: 코드 품질과 모범 사례를 검토. 코드 변경 후 사용.
tools: Read, Glob, Grep
model: sonnet
---

코드를 분석한 뒤 품질, 보안, 모범 사례에 대해
구체적이고 실행 가능한 피드백을 제공하세요.
```

위 예시는 공식 문서의 예시를 한국어로 옮긴 것입니다 [5]. `tools`로 쓸 도구를 제한하고, `model`로 비용이 낮은 모델을 지정할 수 있으며, `isolation: worktree`를 쓰면 임시 git 워크트리에서 격리해 실행합니다 [5].

**시작할 때 로드되는 것.** 서브에이전트는 메인 대화 기록 없이 새로 시작합니다. 자체 시스템 프롬프트, 지정한 스킬 전문, CLAUDE.md와 git 상태, 메인 에이전트가 프롬프트로 넘긴 내용을 받습니다. 대화 전체가 필요하면 포크(fork)로 시작합니다 [2][5].

**현재 한도.** 메인 대화 아래 기본 3계층까지 중첩할 수 있고, 환경 변수 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`로 바꿀 수 있습니다. 동시 실행은 세션당 기본 20개입니다 [5][14].

**시간순 변화.**
- 2026년 6월 8~12일 주간(v2.1.172): 서브에이전트가 다시 서브에이전트를 만들 수 있게 됐습니다 [13].
- 2026년 6월 22~26일 주간: 백그라운드 서브에이전트의 권한 요청이 자동 거부되지 않고 메인 세션에 표시됩니다 [12].
- 2026년 6월 29일~7월 3일 주간: 서브에이전트가 기본적으로 백그라운드에서 실행됩니다 [12].
- 2026년 8월 10~14일 주간: 대화형 세션에서 포크 모드가 기본으로 켜집니다 [12].
- 2026년 10월 31일(v2.1.316): `CLAUDE_CODE_SUBAGENT_EFFORT`가 추가됐습니다 [15].

**병렬 작업의 다른 선택지.** 서브에이전트는 한 세션 안에서만 작동합니다. 공식 문서는 병렬 작업 방식을 다섯 가지로 나눕니다 [6].

| 방식 | 특징 | 상태 |
| --- | --- | --- |
| 서브에이전트 | 한 세션 안의 위임 작업자, 요약 반환 | 정식 기능으로 소개 |
| 에이전트 뷰 | `claude agents`로 백그라운드 세션을 한 화면에서 관리 | 리서치 프리뷰 |
| 에이전트 팀 | 공유 작업 목록과 상호 메시징, 리드가 관리 | 실험적, 기본 꺼짐 |
| 동적 워크플로 | Claude가 쓴 스크립트가 다수의 서브에이전트를 실행하고 교차 검증 | 2026년 5월 말 주간 소개 [12] |
| 프로젝트 | claude.ai/code나 데스크톱 앱에서 장기 작업을 스레드로 병렬 진행 | Pro, Max, Ultra 공개 베타 |

**주의.** 여러 세션이나 서브에이전트를 동시에 돌리면 토큰 사용량도 그만큼 늘어납니다 [6]. 같은 파일을 건드리는 작업은 워크트리로 분리합니다 [6].

**독립 저자의 사례.** Daniil Okhlopkov는 데이터, 프로파일링, 리포트 에이전트를 병렬로 돌려 반나절 걸리던 지갑 분석을 약 15분으로 줄였다고 적었습니다 [21]. 측정 조건이 공개되지 않은 개인 경험담이므로 일반화할 수 없는 수치입니다.

## 4. 훅: 모델의 판단에 맡기지 않는 자동 실행

**정의.** 훅은 Claude Code 수명주기의 특정 시점에 자동으로 실행되는 동작입니다. 공식 문서는 LLM이 실행 여부를 고르게 두지 않고 특정 동작이 반드시 일어나게 하는 "결정적 제어"라고 설명합니다 [7].

**핵심 구분.** 공식 모범 사례는 지시를 두 종류로 나눕니다 [11].
- 비결정적: 프롬프트, CLAUDE.md, 스킬. 모델이 읽고 판단합니다. 대개 따르지만 보장은 없습니다.
- 결정적: 훅, 거부 규칙(deny rule), 관리형 설정. 모델의 판단과 관계없이 Claude Code가 매번 적용합니다.

공식 문서는 CLAUDE.md의 "`.env`를 고치지 마세요"는 부탁이지 보장이 아니며, 이를 막는 `PreToolUse` 훅이 강제 수단이라고 비교합니다 [2]. 공식 블로그의 표현은 "A real guardrail needs to be deterministic"입니다 [16].

다만 공식 문서는 반대쪽도 짚습니다. 대부분의 경우는 Claude가 판단하게 두는 편이 낫고, 단순한 선호에 불과한 훅은 지우라고 권합니다 [11].

**훅 종류 5가지.** `command`(셸 명령), `http`(URL로 POST), `mcp_tool`(MCP 도구 호출), `prompt`(한 번의 LLM 평가), `agent`(도구를 쓰는 다중 턴 검증, 실험적)입니다 [7][8]. 판단이 필요한 조건에는 `prompt`와 `agent`를 쓸 수 있습니다 [7]. 공식 블로그는 앞의 셋은 결정적으로 실행되고 뒤의 둘은 모델의 판단을 쓴다고 구분합니다 [16].

**이벤트.** 현재 가이드 표에 33개 이벤트가 있습니다 [7]. 이 숫자는 공식 문서에 적힌 값이 아니라 표의 행을 에이전트가 센 값입니다. 자주 쓰는 이벤트는 다음과 같습니다.

| 이벤트 | 시점 | 대표 용도 |
| --- | --- | --- |
| `PreToolUse` | 도구 실행 전 (차단 가능) | 보호 파일 수정 막기, 위험 명령 차단 |
| `PostToolUse` | 도구 성공 후 | 포매터, 린터 실행 |
| `Notification` | 알림을 보낼 때 | 입력 대기 알림 |
| `Stop` | 응답을 마칠 때 | 타입 검사 통과 강제 |
| `SessionStart` | 세션 시작 또는 재개 시 | 컴팩션 뒤 맥락 다시 주입 |
| `PreCompact` | 컴팩션 전 | 대화 기록 백업 [16] |

**종료 코드.** 초심자가 가장 많이 헷갈릴 부분입니다 [7][8].
- 종료 코드 0: 이의 없음. `PreToolUse`에서 0은 승인이 아니며, 평소의 권한 흐름을 그대로 거칩니다.
- 종료 코드 2: 차단. stderr에 적은 이유가 Claude에게 피드백으로 전달됩니다. 다만 차단할 수 없는 이벤트에서는 그대로 진행됩니다.
- 그 밖의 코드: 대부분 비차단 오류로 처리되어 동작이 계속됩니다. 일반적인 Unix 실패 코드 1로는 막지 못하므로 정책 강제에는 2를 씁니다.

**설정 예시.** `settings.json`의 `hooks` 키에 넣습니다. 공식 가이드는 개인용 예시에 `~/.claude/settings.json`, 프로젝트용 예시에 `.claude/settings.json`을 씁니다 [7].

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }]
      }
    ]
  }
}
```

공식 가이드는 `.env`, `package-lock.json`, `.git/` 수정을 막는 스크립트를 `PreToolUse`에 등록하는 예시도 제공합니다. 스크립트가 경로를 검사해 `exit 2`로 끝나면 편집이 차단되고 Claude는 그 이유를 전달받습니다 [7]. 확인은 `/hooks`로 합니다 [7].

**동작 방식.** 같은 이벤트에 걸린 훅은 병렬로 실행되고, 모두 끝난 뒤 결과가 합쳐집니다. 한 훅이 거부해도 다른 훅은 계속 실행되며, `PreToolUse`의 권한 결정은 가장 제한적인 답이 적용됩니다 [7]. 기본 타임아웃은 `command`, `http`, `mcp_tool`이 600초, `prompt`가 30초, `agent`가 60초입니다 [8]. 2026년 10월 27일(v2.1.312)부터 `prompt`와 `agent` 훅은 세션당 최대 24개까지 동시에 실행됩니다 [15].

**주의.** `PermissionRequest` 훅의 `matcher`를 `.*`로 쓰거나 비워 두면 파일 쓰기와 셸 명령까지 모든 권한 요청이 자동 승인됩니다. 공식 문서는 범위를 최대한 좁히라고 경고합니다 [7]. 훅의 출력은 컨텍스트에 들어가므로 출력이 많으면 비용이 생깁니다 [2].

## 5. MCP: Claude Code를 외부 세계와 잇는 표준

**정의.** Model Context Protocol은 AI 애플리케이션을 외부 시스템에 연결하는 오픈소스 표준입니다. 공식 사이트는 "AI 애플리케이션의 USB-C 포트"에 비유합니다 [17]. Claude뿐 아니라 ChatGPT, Visual Studio Code, Cursor 등도 지원합니다 [17].

**무엇을 할 수 있나.** 이슈 트래커의 티켓을 읽어 구현한 뒤 GitHub에 PR을 올리고, 데이터베이스를 자연어로 조회하고, Slack에 글을 올리고, 브라우저를 제어할 수 있습니다 [2][9]. 다른 시스템의 데이터를 채팅에 계속 복사하고 있다면 MCP를 도입할 신호입니다 [2][19].

**연결 방법.** HTTP 원격 서버가 권장 방식이고, SSE는 지원 중단 예정이며, 로컬 프로세스는 stdio로 실행합니다 [9].

```bash
# 원격 HTTP 서버 추가
claude mcp add --transport http notion https://mcp.notion.com/mcp

# 로컬 stdio 서버 추가
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable \
  -- npx -y airtable-mcp-server
```

추가한 뒤에는 세션 안에서 `/mcp`로 상태 확인, 인증, 재연결을 합니다. 2026년 6월 말 주간부터는 셸에서 `claude mcp login`으로 인증할 수 있습니다 [9][12].

**범위.** 기본값 `local`은 현재 프로젝트에서 나만 쓰고, `project`는 `.mcp.json`으로 팀과 공유하고, `user`는 내 모든 프로젝트에 적용합니다. 이름이 겹치면 local > project > user 순서로 적용됩니다 [2][9].

**컨텍스트 비용을 줄인 변화: 도구 검색(tool search).** 예전에는 MCP를 많이 붙일수록 도구 정의가 컨텍스트를 차지하는 문제가 있었습니다. 현재는 도구 검색이 기본으로 켜져 있어서, 시작할 때 도구 이름과 서버 지침만 로드하고 전체 스키마는 필요할 때 불러옵니다 [2][9]. 공식 문서는 서버당 고정된 도구 수 제한이 없고 실질적 한계는 컨텍스트 창이라고 설명합니다 [9]. `ENABLE_TOOL_SEARCH` 환경 변수로 동작을 바꿀 수 있고 `false`로 끌 수 있습니다. 일부 구형 모델과 Azure에서 호스팅되는 Microsoft Foundry 배포에서는 처음부터 전부 로드합니다 [9]. 토큰 사용량은 `/context all`로 확인합니다 [2].

**출력 한도.** 도구 출력이 1만 토큰을 넘으면 경고가 뜨고, 기본 상한은 2만 5천 토큰이며 `MAX_MCP_OUTPUT_TOKENS`로 바꿉니다. 상한을 넘은 결과는 파일로 저장되고 대화에는 경로만 남습니다 [9].

**스킬과 함께 쓰기.** MCP는 연결을, 스킬은 그 연결을 잘 쓰는 법을 제공합니다. 예를 들어 MCP로 데이터베이스에 연결하고 스킬에 스키마와 쿼리 패턴을 적어 둡니다 [2].

**보안.** 공식 문서는 연결 전에 서버를 신뢰할 수 있는지 확인하라고 경고합니다. 외부 콘텐츠를 가져오는 서버에는 프롬프트 인젝션 위험이 있습니다 [9]. 프로젝트의 `.mcp.json` 서버는 처음 쓸 때 승인을 요구합니다 [9]. 데이터베이스는 읽기 전용 계정으로 연결하라는 예시가 있습니다 [9].

**독립 저자의 사례.** Okhlopkov는 배포용 Coolify, 메시지용 Telegram, 계획 교차 검토용 Codex MCP를 쓴다고 소개하면서, 서버는 한 번에 많이 붙이지 말고 하나씩 늘리라고 조언합니다 [21].

## 다섯 기능을 함께 쓰는 법

**도입 순서.** 공식 문서가 제시하는 계기는 다음과 같습니다 [2].

| 계기 | 추가할 기능 |
| --- | --- |
| Claude가 규칙이나 명령을 두 번 틀렸다 | CLAUDE.md |
| 같은 프롬프트나 절차를 계속 입력한다 | 스킬 |
| Claude가 못 보는 브라우저 탭의 데이터를 계속 복사한다 | MCP |
| 곁가지 작업의 출력이 대화를 덮는다 | 서브에이전트 |
| 묻지 않아도 매번 일어나게 하고 싶다 | 훅 |
| 다른 저장소에도 같은 설정이 필요하다 | 플러그인 |

**조합 패턴.** 공식 문서의 예시입니다 [2].
- 스킬 + MCP: MCP가 연결하고 스킬이 사용법을 알려 줍니다.
- 스킬 + 서브에이전트: `/audit` 스킬이 보안, 성능, 스타일 서브에이전트를 시작합니다.
- CLAUDE.md + 스킬: CLAUDE.md는 "API 규약을 따르라"고 적고, 전체 가이드는 스킬에 둡니다.
- 훅 + MCP: 중요한 파일이 바뀌면 훅이 MCP로 Slack 알림을 보냅니다.

**최소 구성.** 개인 실사용자인 Okhlopkov는 CLAUDE.md, 서버 하나, 훅 하나, 스킬 하나로 충분하다고 권합니다 [21]. Diget도 CLAUDE.md부터 시작해 반복이 생기면 스킬로, 신뢰성이 필요하면 훅으로 넓히라고 권합니다 [19]. 공식 문서의 순서와 같은 방향입니다 [2].

**여러 곳에 정의됐을 때.** CLAUDE.md는 모두 합쳐지고, 훅도 모두 실행되며, 스킬, 서브에이전트, MCP 서버는 이름 기준으로 하나만 적용됩니다 [2]. 스킬은 개인이 프로젝트보다 우선하고 서브에이전트는 프로젝트가 개인보다 우선하므로, 둘의 순서가 반대입니다 [2].

**플러그인과의 관계.** 플러그인은 여섯 번째 기능이라기보다 포장 계층입니다. 스킬, 에이전트, 훅, MCP 서버를 한 단위로 묶어 설치하고 마켓플레이스로 배포합니다 [2][10]. 단독으로도 다 작동하므로, 여러 프로젝트나 팀에 나눠 줄 때 씁니다 [10]. 플러그인은 사용자 권한으로 실행되므로 설치 전에 검토해야 하며, 활성화해 두면 쓰지 않는 세션에도 이름과 설명이 컨텍스트를 차지합니다 [10].

## 시작 전 기본 정보

- 권장 설치는 macOS, Linux, WSL에서 `curl -fsSL https://claude.ai/install.sh | bash`, Windows PowerShell에서 `irm https://claude.ai/install.ps1 | iex`입니다. Homebrew, WinGet도 지원합니다 [1].
- 설치 후 프로젝트 폴더에서 `claude`를 실행합니다 [1].
- 네이티브 설치는 백그라운드에서 자동 업데이트되지만 Homebrew와 WinGet은 직접 업데이트해야 합니다 [1].
- 대부분의 환경에 Claude 구독이나 Anthropic Console 계정이 필요합니다 [1].
- 저장소의 CLAUDE.md, 설정, MCP 서버는 터미널, IDE, 데스크톱, 웹에서 같은 엔진으로 동작합니다 [1]. 다만 클라우드 세션은 로컬 설정의 플러그인을 로드하지 않습니다 [10].

## 예상 독자 질문

- **CLAUDE.md와 스킬 중 어디에 적나?** 항상 알아야 하면 CLAUDE.md, 가끔 필요하면 스킬입니다 [2].
- **스킬과 훅의 차이는?** 스킬은 Claude가 읽고 해석하는 지침이고, 훅은 이벤트가 생기면 Claude의 판단 없이 실행됩니다 [2].
- **스킬과 서브에이전트의 차이는?** 내용을 불러오는 것이 스킬, 일을 맡기는 작업자가 서브에이전트입니다 [2].
- **스킬과 MCP의 차이는?** MCP는 도구와 데이터 접근을, 스킬은 지식과 절차를 제공합니다 [2].
- **다 설정해야 하나?** 아닙니다. 공식 모범 사례는 대부분의 경우 첫 프롬프트부터 기본값이 잘 작동하도록 만들어졌다고 설명합니다. 설정은 프로젝트 고유의 지식, 규칙, 제약을 Claude가 알 수 없을 때 필요합니다 [11].

- **서브에이전트 중첩 깊이:** 2026년 6월 주간 소식과 공식 블로그는 최대 5단계라고 적었습니다 [13][16]. 현재 서브에이전트 문서와 환경 변수 문서는 기본 3계층이라고 적습니다 [5][14]. 환경 변수 문서에 변경 이력(v2.1.217~218은 기본 1, v2.1.219부터 기본 3)이 있으므로 3계층을 현재 값으로 봅니다. 환경 변수로 조정할 수 있습니다.

- **훅의 결정성:** 공식 블로그는 모든 훅이 결정적으로 트리거된다고 쓰면서도, `prompt`와 `agent` 유형은 모델의 판단을 쓴다고 구분합니다 [16]. 해석: 실행 여부는 결정적이고, `prompt`와 `agent` 유형의 판정 결과는 모델에 달려 있다고 읽는 것이 맞습니다.
- **타사 글의 낡은 정보:** 검색에 나온 타사 글에는 훅 이벤트가 8개라는 설명이나 MCP 설정 위치가 `.claude/settings.json`이라는 설명이 있었습니다. 공식 문서와 다르고 원문을 읽지 않아 근거로 쓰지 않았습니다.
