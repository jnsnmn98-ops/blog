# 네이버 블로그 SEO 가이드 (2026년 11월 기준)

> 작성일: 2026-11-02
> 기준 자료: 네이버 검색 공식 블로그 공지(2016~2026), 2026년 5~6월 「AI 시대에 사용자의 선택을 받는 콘텐츠 작성 가이드」 및 실전편, 2026년 7월 「웹 콘텐츠 스팸 사례」 안내, 네이버 블로그팀 안내(2024), 그 외 업계 분석 자료.

## 0. 먼저 읽을 것: 이 문서의 표기 규칙

네이버 SEO에는 공식 근거가 없는 "공식"이 아주 많습니다. 그래서 모든 항목에 근거 수준을 붙였습니다.

| 표기 | 의미 |
|---|---|
| ✅ **공식** | 네이버 검색 공식 블로그·블로그팀·고객센터가 직접 밝힌 내용 |
| 🟡 **실무 권장** | 공식 수치는 없지만, 공식 원칙과 어긋나지 않는 범위의 현장 관행 |
| ⚠️ **통념(근거 없음)** | 널리 퍼졌지만 네이버가 공식화한 적 없는 수치나 규칙 |

**결론부터 말하면** 네이버는 글자 수, 사진 장수, 키워드 반복 횟수, 해시태그 개수, 발행 빈도에 대해 **숫자 기준을 공식적으로 제시한 적이 없습니다.** 숫자로 된 "정답"은 대부분 ⚠️ 통념입니다. 공식 문서가 반복해서 강조하는 것은 세 가지입니다.

1. 검색 의도에 실제로 답하는 글
2. 직접 경험이 담긴 글
3. 한 주제에 집중하는 블로그

> 참고: 네이버 공식 블로그 원문은 직접 열람이 막혀 있어, 원문을 인용·정리한 2차 자료(출처 목록 참조)를 교차 확인해 작성했습니다. 중요한 의사결정 전에는 원문 링크를 한 번 더 확인하세요.

## 2. 제목 작성 규칙

### 2-1. 공식 원칙 ✅

- **검색어는 제목이나 본문에 포함되어야 검색 대상이 됩니다.** 다만 넣는다고 순위가 오르지는 않습니다. 순위는 사용자 선호도로 정해집니다. (2016)
- **같은 검색어를 제목에 반복하면 불리합니다.** 네이버는 "수분크림"이 다섯 번 반복된 제목을 예로 들어, 선호도가 떨어져 후순위로 밀린다고 설명했습니다. (2016) 2026년 스팸 안내도 제목의 의도적 키워드 반복을 스팸 유형으로 명시했습니다.
- **의미 없는 특수문자로 시선을 끄는 제목은 어뷰징 문서로 규정합니다.** "특수문자를 넣으면 상위 노출된다"는 말은 네이버가 사실이 아니라고 밝혔습니다. (2016)
- **본문과 무관한 업체명이나 문구를 넣으면 낚시성 문서로 분류될 수 있습니다.** (2016, 2026 스팸 안내)
- **실제 명칭을 검색량 많은 다른 이름으로 바꿔 쓰면 스팸입니다.** (2026 스팸 안내)
- **지역명·제품명을 제목에 나열하지 마세요.** 나열할 내용은 본문의 표나 문단으로 정리하는 편이 노출과 전달력 모두에 낫다고 안내했습니다. (2016)
- **홈피드용 제목:** 본문을 담아 직관적이고 간결하게 쓰라고 권합니다. 동어 반복이나 단순 단어 나열은 가독성을 떨어뜨립니다. 제목·본문·썸네일이 자연스럽게 이어져야 합니다. (네이버 블로그팀, 2024-06)

### 2-2. 글자 수

| 항목 | 내용 | 근거 |
|---|---|---|
| 공식 기준 | **없음.** "쉽게 잘 읽힐 수 있는 길이"라는 표현이 전부 | ✅ |
| 실무 권장 | **15~30자.** 모바일 검색 결과에서 잘리지 않는 범위가 기준 | 🟡 |
| 참고 | 15~25자, 25~30자 등 업체마다 숫자가 다름. 2026년 8월 인기글 분석에서는 조회수 상위 글이 30자를 넘기는 경우가 많았다는 데이터도 있음(상관관계일 뿐) | ⚠️ |

**실무 기준:** 핵심이 모바일 첫 줄에 보이도록 **핵심 키워드와 이 글만의 조건을 앞쪽 20자 안에** 둡니다. 나머지 길이는 자유입니다.

### 2-3. 키워드 위치

- **핵심 키워드는 한 번만, 문장 앞쪽에 둡니다.** 🟡 (공식 원칙인 "반복 금지"와 "명확한 제목"을 동시에 만족하는 실무 방식)
- 키워드 뒤에 **이 글만의 범위**를 붙입니다. 예: "3개월 사용", "아이 둘과", "2026년 11월 기준". 경험의 범위가 드러나야 클릭할 이유가 생깁니다. 🟡
- 숫자("5가지", "3분")는 클릭률에 도움이 된다는 의견이 많습니다. 다만 본문과 일치해야 합니다. 🟡

### 2-4. 피해야 할 것

| 피할 것 | 이유 | 근거 |
|---|---|---|
| 같은 키워드 2회 이상 반복 | 선호도 하락, 2026 스팸 유형 | ✅ |
| 의미 없는 특수문자·유니코드·이모지 남발 (★, ♥, 【】, ▶ 등) | 어뷰징 문서로 규정 | ✅ |
| 본문에 없는 업체명·장소·키워드 | 낚시성 문서 | ✅ |
| 실제 명칭 대신 검색량 많은 유사 명칭 | 2026 스팸 유형 | ✅ |
| 지역명·제품명 나열 | 품질이 낮아 보이고 내용 파악이 어려움 | ✅ |
| 이슈 키워드로 제목만 계속 바꿔 끼우기 | 과거 어뷰징 패턴으로 언급됨 | ✅ |
| 과장·자극 표현 ("무조건", "100%", "충격", "역대급") | 본문과 기대가 어긋나면 낚시성 판정 위험, 신뢰도 하락 | 🟡 |
| 의료·건강·금융에서 효과 단정 표현 ("완치", "수익 보장") | 부정확·부적절 정보로 분류될 수 있고 별도 법규 위반 소지 | 🟡 |

### 2-5. 좋은 제목 만드는 순서 🟡

1. 이 글이 답하는 질문을 한 문장으로 적는다. 그 질문의 핵심 명사가 키워드다.
2. 키워드를 한 번만, 앞쪽에 둔다. 실제 명칭을 쓴다.
3. 이 글만의 조건(기간, 대상, 상황, 기준일)을 붙인다.
4. 특수문자와 이모지는 뺀다.
5. 제목만 보고 본문을 열었을 때 기대와 내용이 같은지 확인한다.

```
❌ 강남맛집 강남역맛집 강남 맛집 추천★★ 강남역 데이트
✅ 강남역 파스타 맛집, 평일 저녁 2인 4만 원대로 먹어본 후기
```

## 3. 본문 구조

### 3-1. 네이버 공식 5원칙 ✅ (2026-05-26)

| 원칙 | 내용 | 셀프 체크 |
|---|---|---|
| 직접 경험한 지식 | 직접 겪은 사례, 문제 해결 과정, 실패 경험, 상세한 사용 후기. 전문 주제는 통계·연구·공식 자료 인용 | 남의 글 요약이 아니라 내가 한 일이 있는가 |
| 일관된 주제 | 채널 전체 글의 대부분을 가장 잘 아는 핵심 주제로 | 이 글이 내 블로그 주제 안에 있는가 |
| 거짓 없는 진정성 | 원고료·협찬·내돈내산을 한눈에 표시, 인용 시 원작자와 원문 링크 | 대가 관계와 출처를 밝혔는가 |
| 읽기 쉬운 구조 | 제목·소제목·문단 나누기, 이미지 속 핵심은 텍스트로도 | 소제목만 읽어도 흐름이 잡히는가 |
| 최신성 유지 | 정보가 바뀌면 수정, 새 글을 꾸준히 | 낡은 가격·절차·화면이 남아 있지 않은가 |

### 3-2. 공식 셀프 체크 5항목 ✅ (실전편, 2026-06-04)

1. **독자와 목적:** 누가, 어떤 상황에서 읽는지 정한다. 예: "회의 30분 전에 식사를 마쳐야 하는 직장인" → 동선·가격·소요 시간을 준다.
2. **절차와 구체적 해결 과정:** 시간 순서로 과정, 실패, 수정, 수치를 담는다. 예: 1~30일, 31~60일 단위로 기록.
3. **대안과 비교 분석:** 직접 써 본 A·B·C를 항목별로 비교하고 상황별 선택지를 준다.
4. **실제 적용 사례와 결과:** 환경과 기간을 밝히고 직접 측정한 결과를 쓴다. 제조사 스펙을 옮기는 건 해당하지 않는다.
5. **맥락에 맞는 이미지와 동영상:** 표·리스트·소제목으로 구조화하고 본문과 직접 관련된 미디어만 쓴다.

### 3-3. 글 길이

- ✅ **공식 숫자 기준 없음.** 2024년 안내의 표현은 "도움이 될 만한 충분한 길이의 정보와 분석"이 전부입니다.
- ✅ 2026년 가이드는 사용자가 긴 원문보다 AI 요약을 먼저 보는 데 익숙해지고 있다고 설명합니다. 길이를 채우려는 반복과 군더더기는 평가 대상이 아닙니다.
- ⚠️ "1,500자 이상" "2,000자 이상"은 통념입니다.
- 🟡 **실무 기준:** 셀프 체크 5항목을 다 채우면 대부분 1,500~3,000자 사이가 됩니다. 길이는 목표가 아니라 결과입니다.

### 3-4. 도입-본론-결론 구조와 비율 🟡

공식 비율은 없습니다. 아래는 공식 원칙(두괄식, 읽기 쉬운 구조, AI 인용 친화)에 맞춘 실무 권장 구조입니다.

| 구간 | 비율(권장) | 해야 할 일 |
|---|---|---|
| **도입** | 약 10~15% | ① 독자의 상황·고민을 1~2문장으로 짚는다 ② **핵심 답을 먼저 완결된 한 문단으로 제시**(AI 브리핑 인용용) ③ 이 글의 범위(기간, 대상, 기준일)를 밝힌다 ④ 협찬이면 여기서 표기 |
| **본론** | 약 70~80% | 소제목 3~7개. 과정 → 비교 → 결과 순서. 수치·조건·환경을 구체적으로. 비교는 표, 절차는 번호 리스트 |
| **결론** | 약 10~15% | 핵심 요약 2~3줄, 상황별 추천("이런 분은 A, 이런 분은 B"), 다음 행동. 필요하면 FAQ 2~4개 |

**도입부 핵심:** 첫 화면(모바일 기준 스크롤 전)에서 검색한 사람이 답을 얻어야 합니다. 서론에서 인사말·잡담으로 3~4문단을 쓰는 방식은 피합니다.

### 3-5. 소제목 활용 🟡 (공식 원칙 "읽기 쉬운 구조"의 실무 적용)

- **소제목만 읽어도 글의 흐름이 잡히게** 씁니다. (✅ 공식 체크 문항)
- 소제목을 **독자가 실제로 검색할 질문 형태**로 씁니다. 예: "가격은 얼마인가요?", "주차는 가능한가요?" → 제목에 못 넣은 연관 키워드가 억지 없이 들어갑니다.
- **소제목 바로 아래 첫 문장에 답을 둡니다.** (답변 우선 구조, AI 브리핑 인용에 유리)
- 스마트에디터의 **소제목 서식**을 실제로 적용합니다. 굵은 글씨로만 꾸민 문장은 구조로 인식되지 않을 수 있습니다.
- 문단은 3~5문장 단위로 나누고, 모바일에서 한 화면에 텍스트 벽이 생기지 않게 합니다.
- 비교 정보는 표로, 단계는 번호 리스트로, 핵심 한 줄은 인용구로 정리합니다.

### 3-6. 신뢰를 높이는 본문 요소 ✅/🟡

- 출처가 있는 사실은 출처를 밝힌다(공식 자료, 통계). ✅
- 인용할 때는 원작자와 원문 링크를 단다. ✅
- 날짜 기준을 적는다("2026년 11월 기준 가격"). 🟡
- 같은 주제의 이전 글을 본문에 자연스럽게 연결한다(내부 링크). 🟡
- 장소 글이면 네이버 지도를 첨부한다. 🟡

## 4. 키워드 밀도와 배치

### 4-1. 공식 입장 ✅

- **반복 횟수 기준은 없습니다.** 네이버는 "몇 회가 적당하다"를 공식화한 적이 없습니다.
- **인위적 반복은 불리합니다.** 제목과 본문에 검색어를 인위적으로 반복한 문서는 후순위로 밀린다고 설명했습니다. (2016)
- **2026년 스팸 안내는 동일 키워드의 의도적 반복을 스팸 유형으로 명시했습니다.**
- **무관한 키워드 삽입은 "외면받는 글" 유형입니다.** (2026 가이드)
- D.I.A.+는 문서가 검색 의도에 맞는 내용을 **실제로 담고 있는지**까지 판별합니다. 키워드만 있고 내용이 없으면 오히려 낚시성으로 봅니다. (2020)

### 4-2. 밀도

| 주장 | 평가 |
|---|---|
| "키워드 밀도 1.5~3% 유지" | ⚠️ 업계 통념. 공식 근거 없음 |
| "본문에 키워드 5~7회" | ⚠️ 통념. 2026년에는 오히려 위험 신호로 보는 시각이 많음 |
| **실무 기준** | 🟡 **횟수를 세지 않는다.** 자연스럽게 읽었을 때 어색한 문장이 하나라도 있으면 줄인다 |

**왜 세지 않아도 되나:** 2026년 네이버 검색은 문맥 기반 매칭(신경망 매칭)이 강화되어, 검색 의도에 맞으면 정확한 키워드가 덜 들어가도 노출될 수 있다는 분석이 많습니다. 🟡 반대로 반복은 공식적으로 손해입니다. ✅

### 4-3. 배치 🟡

| 위치 | 권장 | 비고 |
|---|---|---|
| 제목 | 핵심 키워드 1회, 앞쪽 | 2장 참조 |
| 도입부 첫 2~3문장 | 핵심 키워드 1회, 자연스럽게 | 검색자가 "맞게 찾아왔다"고 확인하는 구간 |
| 소제목 | 연관 키워드·질문형 키워드 분산 | 같은 키워드를 소제목마다 반복하지 않기 |
| 본론 | 동의어·연관어·구체 명사로 풀어 쓰기 | 예: "다이어트 도시락" → 칼로리, 단백질, 1회분, 냉동 보관 |
| 결론 | 필요하면 1회 | 억지로 넣지 않기 |
| 사진 설명(캡션) | 사진 내용을 설명하는 문장 속에 자연스럽게 | 키워드만 나열 금지 |
| 태그 | 핵심·연관 키워드 | 5장 참조 |

**핵심 원칙:** 같은 단어를 반복하는 대신 **같은 주제의 다른 단어(연관어, 구체 명사, 수치)를 늘립니다.** 이것이 주제 적합도와 정보 충실성을 동시에 올리는 방법입니다. 🟡

## 5. 이미지

### 5-1. 몇 장이 적절한가

| 항목 | 내용 | 근거 |
|---|---|---|
| 공식 입장 | **이미지 수는 검색 랭킹과 직접적인 연관성이 없다** | ✅ 2016 |
| 많이 넣으면 | 필요 없는 이미지를 의도적으로 늘리면 방문자 만족도가 떨어져 오히려 검색에 좋지 않다 | ✅ 2016 |
| 피하면 | 필요한 이미지까지 피할 이유는 없다 | ✅ 2016 |
| "10장 이상", "15장 이상" | 통념 | ⚠️ |
| **실무 기준** | **설명에 필요한 장면마다 1장.** 과정 글은 단계마다, 후기 글은 근거가 되는 장면마다. 대부분 5~15장 사이가 된다 | 🟡 |

### 5-2. 어떤 이미지를 쓰나

- **직접 찍은 사진**을 씁니다. 다른 출처 이미지는 저작권 분쟁과 **유사 문서 분류 위험**이 있습니다. ✅ 출처 표시만으로 저작권 문제가 해결되지는 않습니다.
- **같은 조건이면 큰 이미지가 이미지 검색에서 더 위에 나옵니다.** 다만 가중치에 한계가 있어 무리하게 키울 필요는 없습니다. 휴대폰 원본 수준이면 충분합니다. ✅
- **본문과 무관한 이미지·동영상을 의미 없이 나열하지 마세요.** 2026 가이드가 "외면받는 글" 유형으로 꼽았습니다. ✅
- **이미지 속 핵심 정보는 텍스트로도 씁니다.** 가격표, 메뉴판, 표 이미지의 내용을 본문에 글로 다시 적어야 검색과 AI 브리핑이 읽을 수 있습니다. ✅
- **글 끝 서명 이미지처럼 같은 이미지 1장을 반복하는 정도는 괜찮습니다.** 문제는 본문 이미지 대부분이 다른 글과 겹치는 경우입니다. ✅
- **홍보 문구 이미지를 모든 글에 도배하면 신뢰도에 나쁜 영향을 줍니다.** ✅
- **사실로 오인될 수 있는 합성·생성 이미지는 피해 유발 콘텐츠로 분류됩니다.** 설명용 일러스트는 괜찮지만, 후기나 현장 사진 자리에 AI 생성 이미지를 쓰지 마세요. ✅ (2026 스팸 안내)
- **유해 이미지가 있는 문서는 검색에서 빠지고, 심하면 블로그 전체가 제외됩니다.** ✅
- 짧은 영상이나 클립(숏폼)을 함께 넣으면 체류와 통합검색 노출에 도움이 된다는 분석이 많습니다. 🟡

### 5-3. alt 텍스트 (대체 텍스트)

| 항목 | 내용 | 근거 |
|---|---|---|
| 일반 웹 원칙 | 검색 로봇은 텍스트를 읽으므로 이미지에 설명을 달아야 함 | ✅ 네이버 서치어드바이저 웹마스터 가이드 |
| 네이버 블로그 | 스마트에디터는 HTML alt를 직접 편집하는 구조가 아님. 일부 자료는 "네이버는 alt 텍스트를 지원하지 않는다"고 안내 | 🟡 확인 필요 |
| **실무 대안** | **사진 설명(캡션) 기능 + 사진 앞뒤 본문 문장**으로 이미지 내용을 설명 | 🟡 |

**캡션·설명 작성법** 🟡

- 무엇이, 어떤 상황에서, 왜 보이는지를 한 문장으로 씁니다.
  - ❌ "강남맛집 파스타 강남역맛집"
  - ✅ "트러플 크림 파스타 1인분, 면 양은 성인 남성 기준 넉넉한 편"
- "사진", "이미지" 같은 단어는 빼고 내용에 집중합니다.
- 키워드 나열은 스팸 신호입니다. 문장 안에 자연스럽게 넣습니다.
- 파일명도 의미 있게(예: `gangnam-truffle-pasta.jpg`) 올리는 습관을 권합니다. 효과는 공식 확인되지 않았습니다. 🟡

### 5-4. 대표 이미지(썸네일) 규격

| 항목 | 내용 | 근거 |
|---|---|---|
| 썸네일 결정 방식 | 검색 결과와 홈피드 썸네일은 글의 **대표 이미지** | ✅ |
| 최소 크기 | 네이버 블로그 가로·세로 각 **40px 이상**(외부 블로그는 150px) | ✅ 2016 안내 |
| 노출 제외 | 너무 작거나, **가로·세로 비율 차이가 지나치게 큰** 이미지(길쭉하거나 납작한 이미지)는 썸네일로 쓰이지 않음 | ✅ 2016 |
| 권장 크기 | 공식 숫자 없음 | ✅ |
| **실무 권장** | **정사각형 1:1(예: 1080×1080px) 또는 4:3 근처**, 핵심 피사체를 가운데 배치. 화면별로 잘려도 핵심이 남게 | 🟡 |

**네이버 블로그팀 커버 이미지 권장 사항** ✅ (2024-06)

| 권장 | 비권장 |
|---|---|
| 글의 매력이 가장 잘 느껴지는 핵심 사진 1장 | 사진 위에 텍스트를 가득 얹은 이미지 |
| 전체 인상이 보이는 구도 | 여러 장을 붙인 분할 이미지 |
| 주제에 따라 핵심을 **짧은 문구**로 2차 편집한 이미지 | 위아래가 잘려 핵심이 안 보이는 크롭 |
| 제목·본문과 자연스럽게 이어지는 이미지 | 본문과 관련 없는 이미지 |

- 정보형 글(비교, 순서, 수치)은 짧은 문구 썸네일이 도움이 되고, 장소·음식처럼 사진 자체가 정보인 글은 문구가 오히려 핵심을 가립니다. 🟡
- 모든 글에 같은 틀의 문구 썸네일을 찍어내는 방식은 피합니다(홍보 이미지 도배와 유사). 🟡
- 썸네일 디자인 자체는 공식 순위 요소가 아닙니다. 다만 클릭과 홈피드 선택을 통해 간접적으로 작용합니다. ✅/🟡

## 6. 해시태그(태그) 활용법

### 6-1. 공식 확인 사항

- ✅ 네이버가 태그를 **검색 순위 요소로 공식화한 적은 없습니다.** 업계에서도 상위 노출에 직접 영향이 없다는 의견이 다수입니다.
- ✅ **노출만을 위해 맥락 없는 키워드를 끼워 넣는 것**은 2026 가이드의 "외면받는 글" 유형입니다. 태그에도 그대로 적용된다고 보는 것이 안전합니다.

### 6-2. 태그가 실제로 하는 일 🟡

| 환경 | 태그 클릭 시 | 의미 |
|---|---|---|
| PC | 내 블로그에서 같은 태그를 단 글만 보임 | 블로그 안 분류(색인) 기능 |
| 모바일 | 같은 태그를 단 **모든 블로거의 글**이 최신순으로 보임 | 소량의 추가 유입 경로 |
| 홈피드·주제 분류 | 글 주제를 시스템이 파악하는 보조 신호로 쓰인다는 분석이 있음 | 공식 확인 없음 |

### 6-3. 개수

| 주장 | 평가 |
|---|---|
| 글당 최대 30개 | ⚠️ 흔히 인용되지만 공식 문서로 확인하지 못함. 에디터에서 직접 확인 필요 |
| "4개 이상 쓰면 불리" / "30개 꽉 채워야 유리" | ⚠️ 둘 다 근거 없음 |
| **실무 기준** | 🟡 **5~10개.** 본문에 실제로 나오는 핵심·연관 단어만 |

### 6-4. 작성 규칙 🟡

1. **핵심 키워드 1~2개 + 연관어·세부 주제 3~6개 + 고유명사(장소명, 제품명) 1~2개** 정도로 구성합니다.
2. **본문에 실제로 다룬 내용만** 태그로 답니다. 본문에 없는 인기 키워드·이슈 키워드는 넣지 않습니다.
3. 띄어쓰기만 다른 같은 단어를 여러 개 달지 않습니다. (예: #강남맛집 #강남 맛집 #강남역맛집 #강남역 맛집)
4. 모든 글에 같은 태그 묶음을 복사해 붙이지 않습니다. 글마다 다른 내용이면 태그도 달라야 합니다.
5. 본문 중간에 #태그를 줄줄이 넣지 말고 글 끝 또는 발행 태그 칸에 모읍니다.
6. 이미 발행한 글의 태그를 고치려고 수정을 반복할 필요는 없습니다.

```
❌ #강남맛집 #강남역맛집 #서울맛집 #맛집추천 #데이트 #핫플 #먹스타그램 #일상 #오늘뭐먹지 #인기 ... (30개)
✅ #강남역파스타 #트러플크림파스타 #강남역데이트 #평일저녁 #2인코스
```

## 7. C-Rank와 D.I.A.+ 알고리즘이 좋아하는 패턴

### 7-1. 공식 정의 ✅

| 구분 | C-Rank | D.I.A. / D.I.A.+ |
|---|---|---|
| 평가 대상 | **출처(블로그)** | **개별 문서** |
| 네이버 설명 | 출처의 신뢰도·인기도를 랭킹에 반영 | 키워드별로 사용자가 선호하는 문서 점수를 랭킹에 반영 |
| 공개된 요소 | Context(주제 집중도), Content(정보 품질), Chain(소비·생산 연쇄반응), Creator(신뢰도·인기도) | 주제 적합도, 경험 정보, 정보의 충실성, 문서의 의도, 상대적 어뷰징 척도, 독창성, 적시성 |
| 발행 주기와의 관계 | 주제 집중과 활동성이 영향 | 문서 품질만 보므로 작성 주기와 무관 |
| 업데이트 | 매일 진화, 실시간 반영 | 딥러닝으로 품질 기준값이 주기적 자동 업데이트 |

- ✅ 두 알고리즘은 **상호 보완적**입니다. C-Rank가 높은 작가가 대체로 D.I.A. 점수도 높은 문서를 썼고, 둘 중 하나라도 높으면 유리합니다.
- ✅ **항상 상위 노출이 보장되는 출처는 없습니다.**
- ✅ 랭킹에는 C-Rank, D.I.A.+ 외에도 **유사문서 판독 시스템** 등 여러 알고리즘이 함께 작동하며, 가중치는 공개되지 않았습니다.
- ✅ "블로그 지수", "최적화 블로그", "저품질 블로그"는 **네이버가 만든 개념이 아니라고** 밝혔습니다. (2016) 지수 사이트의 숫자는 외부 업체의 추정치입니다.
- ✅ C-Rank·D.I.A.는 블로그 검색 로직으로 설명된 모델입니다. **AI 브리핑 출처 선정에 같은 점수가 직접 쓰인다고 공개된 적은 없습니다.**

### 7-2. C-Rank가 좋아하는 패턴

| 패턴 | 설명 | 근거 |
|---|---|---|
| **한 주제 집중** | 블로그 전체 문서의 주제 분포로 집중도를 계산. 특정 주제에 대한 자신만의 글이 늘수록 잘 노출됨 | ✅ |
| 핵심 주제가 채널의 대부분 | 2026 가이드도 채널 글 대부분을 가장 잘 아는 주제로 채우라고 권함 | ✅ |
| 기업 블로그는 업종 주제만 | 전문성과 무관한 일상 글은 검색에 도움이 되지 않음 | ✅ |
| 꾸준한 활동 | 장기간 방치하면 떨어질 수 있지만, 다시 관리하면 회복됨 | ✅ |
| 빈도보다 만족도 | 가끔이라도 좋은 문서를 쓰고 만족을 주는 출처가 더 노출되도록 개선 | ✅ 2018 |
| 같은 주제 글끼리 연결 | 시리즈, 내부 링크로 주제 묶음을 만들기 | 🟡 |
| 외부에서 언급·인용되는 글 | 다른 출처에서의 관심이 신뢰도·인기도 계산에 쓰인다는 설명이 있음 | 🟡 |

**블로그 주제 설계 팁** 🟡

- 핵심 주제 1개 + 바로 인접한 보조 주제 1~2개로 운영합니다.
- 카테고리를 주제 단위로 정리하고, 주제와 무관한 일상 글은 비공개 카테고리로 분리하거나 줄입니다.

### 7-3. D.I.A.+가 좋아하는 패턴

| 패턴 | 설명 | 근거 |
|---|---|---|
| **경험 정보** | 직접 써 보고, 가 보고, 해 본 과정과 결과 | ✅ 반영 요소 |
| **정보의 충실성** | 가격, 소요 시간, 준비물, 조건, 수치처럼 독자가 실제로 궁금한 정보 | ✅ |
| **검색 의도 일치** | 경험·의견·리뷰를 찾는 검색인지, 정보를 찾는 검색인지 분석해 그에 맞는 문서를 올림 | ✅ D.I.A.+ |
| **독창성** | 다른 글과 겹치지 않는 고유한 내용과 사진 | ✅ |
| **적시성** | 내용이 최신인지. 발행 빈도가 아니라 **문서 내용의 최신성** | ✅ |
| **문서 패턴** | 구조, 본문 텍스트, 이미지 정보에서 추출한 패턴을 랭킹에 활용 | ✅ D.I.A.+ |
| **대가성 표기** | 협찬·지원을 받았다면 모든 글에 명확히 표기. 미표기 시 강한 제재 가능 | ✅ D.I.A.+ |

### 7-4. AI 브리핑 인용까지 노리는 패턴 🟡 (공식 원칙 기반)

- 별도의 "AI 브리핑 전용 작업"은 공식적으로 없습니다. 공식 가이드가 첫 조건으로 든 것은 **직접 경험한 지식**입니다. ✅
- 글 맨 앞에 질문에 대한 답을 **완결된 한 문단**으로 둡니다.
- 소제목을 실제 검색 질문 형태로 쓰고, 바로 아래에 답을 둡니다.
- 비교 정보는 표로, 단계는 번호 리스트로 만듭니다.
- "~할 수 있습니다" 같은 모호한 서술보다 **조건과 결과를 명시**합니다. 예: "평일 오후 2시 기준 대기 없음, 주말 12시엔 40분 대기"
- 출처가 있는 사실은 출처를 밝힙니다.
- 이미지로 전달하는 정보는 텍스트로도 적습니다. ✅
- 성과는 발행 건수가 아니라 **인용 여부**로 셉니다. 네이버 메이트도 인용 수 기준입니다. ✅

### 7-5. AI 도구 사용에 대한 공식 입장 ✅

| 시점 | 내용 |
|---|---|
| 2024-02 | 생성 방식과 관계없이 좋은 문서는 노출 가능. AI 활용 사실 **명시를 권고**. AI로 비슷한 글을 대량 생산하는 것은 어뷰징 예시 |
| 2025-02 | LLM 기반 평가로 자동 생성 저품질 콘텐츠·경험 없는 광고 도배글 판별 강화 |
| 2026-05 | AI 사용만으로 패널티 없음. 최종 검토·편집으로 **실제 경험을 녹일 것.** 기계적으로 생성·요약한 글은 걸러질 수 있음 |
| 2026-07 | 저품질 대량 생성은 특정 기술 사용 여부만으로 판단하지 않음. 결과물로 판단 |

**결론:** AI로 초안을 잡는 것은 괜찮습니다. 다만 **직접 경험, 직접 찍은 사진, 직접 측정한 수치**는 사람이 채워야 합니다.

## 8. 어뷰징으로 판정되는 것들 (피해야 할 것)

### 8-1. 공식 스팸·어뷰징 유형 ✅

**제목·키워드**

- [ ] 제목·본문에 동일 키워드를 의도적으로 반복
- [ ] 노출만을 위해 맥락 없는 키워드 삽입
- [ ] 실제 명칭 대신 검색량 많은 키워드로 바꿔 쓰기
- [ ] 의미 없는 특수문자·유니코드로 제목 꾸미기
- [ ] 제목과 본문이 일치하지 않는 낚시성 글 (본문과 무관한 업체명·장소·문구)

**콘텐츠 원본성**

- [ ] 다른 글 복사·붙여넣기, 인기글 베끼기
- [ ] 확인되지 않은 사실 짜깁기
- [ ] 생성형 AI 등으로 비슷한 글을 대량 생산·발행
- [ ] 다른 사람이 찍은 사진을 가져와 재업로드 (저작권 + 유사 문서 위험)
- [ ] 본문 이미지 대부분을 다른 글과 공유

**광고·대가성**

- [ ] 원고료·협찬·제품 제공 사실 미표기 또는 찾기 어렵게 표기
- [ ] 핵심과 무관한 광고 문구 과다
- [ ] 홍보 목적 외부 URL 과다 삽입
- [ ] 홍보 문구 이미지를 거의 모든 글에 도배
- [ ] 실제 경험 없는 광고성 도배글

**미디어**

- [ ] 본문과 무관한 이미지·동영상을 의미 없이 나열
- [ ] 사실로 오인될 수 있는 합성·생성 이미지 (피해 유발 콘텐츠)
- [ ] 유해 이미지 (심하면 블로그 전체가 검색에서 제외)

**정보 품질**

- [ ] 사실 확인 없이 부정확하거나 부적절한 정보 배포

**활동 조작**

- [ ] 스크랩·댓글·공감 품앗이, 자동화 프로그램으로 지표 부풀리기 (이런 지표는 직접 랭킹에 쓰지 않으며, 의도적으로 올리면 어뷰징 블로그로 분류될 수 있음)
- [ ] 대량 아이디로 이웃 관계를 기계적으로 맺기
- [ ] 정확히 일정한 시간 간격의 기계적 발행 (어뷰징으로 오판될 수 있다고 안내)
- [ ] 비정상적인 속도의 자동 입력(매크로)

**수정 패턴**

- [ ] 내용은 그대로 두고 이슈 키워드만 바꿔 끼우는 반복 수정

**검색엔진 공통 스팸** ✅ (서치어드바이저 가이드·검색엔진 공통 원칙)

- [ ] 배경과 같은 색 글씨, 0 크기 글꼴 등으로 텍스트 숨기기
- [ ] 키워드를 목록·묶음으로 부자연스럽게 채워 넣기

### 8-2. 공식적으로 문제가 아닌 것 ✅ (오해 바로잡기)

| 소문 | 사실 |
|---|---|
| "글을 수정하면 불이익" | 근거 없음. 정보가 바뀌면 수정하라고 2026 가이드가 직접 권함 |
| "매일 써야 지수가 오른다" / "하루 1~3개, 시간 간격을 두고" | 잘못된 소문으로 분류. 쓸 내용이 있을 때 제대로 쓰기 |
| "90일 쉬면 저품질" | "저품질"이라는 제재 상태 자체가 공식 개념이 아님 |
| "제목에 특수문자를 쓰면 무조건 제재" | 특수문자 사용만으로 정상 글이 제재받지는 않음. 의미 없는 과도한 사용이 문제 |
| "안 좋은 블로그와 이웃 맺으면 같이 나빠진다" | 직접 영향 없음 |
| "IP가 바뀌면 불리" | 일상적 상황이라 영향 없음 |
| "AI로 쓰면 패널티" | 사용만으로는 없음. 결과물의 품질로 판단 |
| "같은 서명 이미지를 반복하면 유사 문서" | 글 끝 이미지 1장 정도는 영향 없음 |

### 8-3. 누락이 생겼을 때 🟡

1. 누락이 곧 저품질은 아닙니다. 반영 지연, 일부 글만의 문제인지 먼저 구분합니다.
2. 최근 글의 공통점을 봅니다: 키워드 반복, 무관 태그, 외부 링크 과다, 대가성 미표기, 복사 이미지.
3. 문제 요소를 고치고, 이후 글은 위 체크리스트를 지켜 꾸준히 발행합니다.
4. 새 블로그를 만드는 것은 마지막 수단입니다. 원인이 같으면 새 블로그에서도 반복됩니다.

## 9. 발행 전 최종 체크리스트

**제목**
- [ ] 핵심 키워드 1회, 앞쪽에 있는가
- [ ] 이 글만의 조건(기간·대상·기준일)이 붙었는가
- [ ] 특수문자·반복·본문에 없는 단어가 없는가

**본문**
- [ ] 첫 화면에서 검색 질문에 대한 답이 나오는가
- [ ] 직접 경험한 과정·수치·결과가 있는가
- [ ] 소제목만 읽어도 흐름이 잡히는가
- [ ] 비교는 표, 절차는 리스트로 정리했는가
- [ ] 같은 키워드를 어색하게 반복한 문장이 없는가
- [ ] 정보의 기준일과 출처를 밝혔는가
- [ ] 내 블로그의 핵심 주제 안에 있는 글인가

**이미지**
- [ ] 직접 찍은 사진인가
- [ ] 설명에 필요한 장면만 넣었는가
- [ ] 이미지 속 핵심 정보를 텍스트로도 적었는가
- [ ] 사진 설명(캡션)을 문장으로 달았는가
- [ ] 대표 이미지가 정사각형 근처, 핵심이 가운데, 문구는 짧은가

**태그**
- [ ] 5~10개, 본문에 실제로 나온 단어만 달았는가
- [ ] 중복·인기 키워드 끼워 넣기가 없는가

**신뢰**
- [ ] 협찬·원고료·내돈내산을 글 앞부분에 한눈에 표시했는가
- [ ] AI를 활용했다면 활용 사실을 밝혔는가(권고 사항)
- [ ] 외부 홍보 링크가 과하지 않은가
